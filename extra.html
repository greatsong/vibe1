1. 데이터가 쌓이는 앱 — 구글 시트

오늘 만든 앱은 새로고침하면 화면에 넣은 내용이 사라집니다. 저장소를 하나 붙이면 남습니다. 여기서 만드는 것은 약속 잡기 앱입니다. 이름과 가능한 시간을 제출하면 표에 한 줄씩 쌓이고, 다른 사람이 다른 기기에서 열어도 그대로 보입니다.

  • 저장소는 구글 시트입니다. 새로 가입할 서비스가 없고, 쌓인 데이터를 익숙한 표 화면에서 바로 봅니다
  • 앱에서 연결에 필요한 것은 중계 주소(웹 앱 URL) 한 줄입니다. 오늘 STEP 2에서 다룬 비밀 금고(secrets) 방식 그대로입니다
  • 오프닝에서 본 '전국 선생님 지도'가 바로 이 방식으로 돌아갑니다
  • 준비 15분, 앱 만들기 15분 정도 걸립니다

1-1. 시트와 중계 프로그램 만들기

앱이 구글 시트를 직접 여는 것이 아니라, 시트 앞에 중계 프로그램(Apps Script)을 하나 세워 둡니다. 앱은 중계 주소로 저장을 부탁하고, 같은 주소를 열어 명단을 받아 옵니다.

  1. 새 스프레드시트 만들기
    구글 계정으로 로그인한 브라우저에서 sheets.new를 열면 빈 스프레드시트가 하나 생깁니다. 이름은 약속잡기 정도로 정합니다. 시트(탭)를 미리 만들 필요는 없습니다. 첫 제출이 들어올 때 votes 시트가 자동으로 생깁니다.
  2. Apps Script 열고 코드 붙여넣기
    스프레드시트 메뉴에서 확장 프로그램 → Apps Script를 누르면 코드 편집기가 새 탭으로 열립니다. 기본으로 있는 내용을 지우고 아래 상자를 그대로 붙여넣은 뒤 저장(💾)합니다.
  3. 웹 앱으로 배포
    오른쪽 위 배포 → 새 배포를 누르고, ⚙️(톱니)에서 유형을 웹 앱으로 고릅니다. 실행 계정: 나, 액세스 권한: 모든 사용자로 두고 배포를 누릅니다. 처음이면 권한 승인 창이 뜹니다. 내 계정을 고르고, '확인되지 않은 앱' 경고가 나오면 고급 → (프로젝트 이름)(으)로 이동 → 허용을 누릅니다. 내가 만든 코드에 내 시트를 열어 주는 절차라 놀랄 것 없습니다.
  4. 웹 앱 URL 복사
    배포가 끝나면 https://script.google.com/macros/s/…/exec 모양의 주소가 나옵니다. 끝이 /exec인 이 주소가 중계 주소입니다. 새 탭에서 열어 {"ok":true로 시작하는 글자가 보이면 준비가 끝난 것입니다.
Apps Script에 그대로 붙여넣고 저장 (Code.gs)
const SHEET_NAME = 'votes';

function sheet_() {
  const ss = SpreadsheetApp.getActiveSpreadsheet();
  let sh = ss.getSheetByName(SHEET_NAME);
  if (!sh) {
    sh = ss.insertSheet(SHEET_NAME);
    sh.appendRow(['제출시각', '이름', '가능한시간']);
  }
  return sh;
}

// 한 건 저장 (앱이 보내는 제출)
function doPost(e) {
  const lock = LockService.getScriptLock();
  lock.waitLock(30000);
  try {
    const d = JSON.parse(e.postData.contents);
    sheet_().appendRow([new Date(), d.name || '', d.times || '']);
    return out_({ ok: true });
  } catch (err) {
    return out_({ ok: false, error: String(err) });
  } finally {
    lock.releaseLock();
  }
}

// 명단 전체 반환 (앱이 여는 요청) — 최근 제출이 앞으로
function doGet(e) {
  const sh = sheet_();
  const rows = [];
  if (sh.getLastRow() > 1) {
    sh.getRange(2, 1, sh.getLastRow() - 1, 3).getValues().forEach(function (r) {
      rows.push({ created_at: r[0], name: String(r[1]), times: String(r[2]) });
    });
  }
  rows.reverse();
  return out_({ ok: true, rows: rows });
}

function out_(obj) {
  return ContentService.createTextOutput(JSON.stringify(obj))
    .setMimeType(ContentService.MimeType.JSON);
}
  • 저장(doPost)과 읽기(doGet) 두 가지가 전부입니다. 앱은 이 둘만 부릅니다
  • 여러 명이 동시에 제출해도 줄이 엉키지 않도록 저장에는 잠금(Lock)을 걸어 두었습니다
  • 제출 시각은 중계 프로그램이 알아서 채웁니다. 앱에서 보낼 필요가 없습니다
⚠️ 배포 설정이 조용히 막습니다
  • 액세스 권한이 '모든 사용자'가 아니면 앱의 요청이 구글 로그인 화면으로 돌아옵니다. 앱 입장에서는 명단 대신 로그인 페이지가 온 것이라 Expecting value 같은 오류가 납니다
  • 코드를 고쳤다면 저장만으로는 반영되지 않습니다. 배포 → 배포 관리 → ✏️ → 버전: 새 버전 → 배포를 눌러야 바뀐 코드가 나갑니다. 주소는 그대로 유지됩니다
  • 가장 흔한 사고는 편집기 주소를 금고에 넣는 것입니다. …/edit로 끝나면 편집기 주소, …/exec로 끝나야 중계 주소입니다
  • 확인 방법은 하나면 됩니다. 중계 주소를 브라우저에서 직접 열어 {"ok":true가 보이면 통과입니다
🔑 키는 없습니다. 그래도 주소는 금고에
  • 이 방식에는 따로 키가 없습니다. 중계 주소 하나가 전부입니다
  • 주소를 아는 사람은 누구나 읽고 쓸 수 있습니다. 반 전체가 함께 쓰는 공용 노트라고 생각하고, 민감한 정보는 담지 않습니다
  • 그래도 주소를 코드에 적지 않고 금고에 두는 습관은 그대로 유지합니다. 저장소를 공개해도 주소가 드러나지 않고, 주소를 바꿀 때 코드를 건드리지 않아도 됩니다

1-3. AI에게 주문하기

① 샘플 프롬프트
스트림릿으로 '약속 잡기' 앱 하나(main.py)를 만들어줘. 스트림릿 클라우드에 올릴 거야.

- 데이터 저장소는 구글 시트고, 시트 앞에 세워 둔 중계 주소(Apps Script 웹 앱)로만
  읽고 써. 중계 주소는 비밀 금고(secrets)의 SHEET_API_URL에서 꺼내 써.
  코드에는 적지 마.
- 저장할 때는 중계 주소로 이름(name)과 가능한 시간(times)을 JSON으로 보내면 돼.
  제출 시각은 중계 프로그램이 알아서 채우니까 앱에서 보내지 마.
- 읽을 때는 중계 주소를 그대로 열면 ok와 rows가 든 JSON이 오고,
  rows 안에 한 줄마다 name, times, created_at이 들어 있어. 최근 제출이 앞이야.
- 화면 위에 이름 입력창, 가능한 시간을 여러 개 고르는 목록, 제출 버튼을 둬.
  시간 목록은 '월 오전'부터 '금 오후'까지 요일과 오전·오후를 짝지은 열 개로.
- 제출을 누르면 이름과 고른 시간을 한 줄로 보내줘.
  여러 개 고른 시간은 쉼표로 이어 붙여서 times 한 칸에 넣어.
- 이름이 비었거나 시간을 하나도 안 골랐으면 저장하지 말고 안내 문구만 띄워.
- 그 아래에는 명단 전체를 표로 보여줘. 표에는 이름과 시간 두 열만 보이면 돼.
  아직 한 줄도 없으면 표 대신 비어 있다는 안내를 띄워.
- 필요한 라이브러리 목록(requirements.txt)도 같이 줘.
  버전 숫자 없이 이름만, 스트림릿·판다스·넘파이는 기본 설치라 빼고.
- 한국어 라벨, 초보자용 한국어 주석. main.py 전체 코드를 한 번에 줘.
  • AI가 아래와 같은 모습의 코드를 줍니다. 글자까지 똑같지 않아도 됩니다
② AI가 준 코드 예시 (main.py)
import streamlit as st
import requests
import pandas as pd

# 비밀 금고(secrets)에 넣어 둔 중계 주소(웹 앱 URL)를 꺼냅니다
API_URL = st.secrets["SHEET_API_URL"]

st.set_page_config(page_title="약속 잡기", page_icon="📅")
st.title("📅 약속 잡기")
st.write("가능한 시간을 골라 제출하면 아래 명단에 한 줄씩 쌓입니다.")

시간목록 = [
    "월 오전", "월 오후", "화 오전", "화 오후", "수 오전",
    "수 오후", "목 오전", "목 오후", "금 오전", "금 오후",
]

이름 = st.text_input("이름")
선택시간 = st.multiselect("가능한 시간을 모두 고르세요", 시간목록)

if st.button("제출"):
    if not 이름:
        st.warning("이름을 적어 주세요.")
    elif not 선택시간:
        st.warning("가능한 시간을 하나 이상 골라 주세요.")
    else:
        # 여러 개 고른 시간은 쉼표로 이어 한 칸에 넣습니다
        requests.post(
            API_URL,
            json={"name": 이름, "times": ", ".join(선택시간)},
        )
        st.success(f"{이름} 선생님, 제출됐습니다.")

st.divider()
st.subheader("📋 지금까지 제출된 명단")

# 중계 주소를 열어 명단 전체를 받아 옵니다 (최근 제출이 앞)
데이터 = requests.get(API_URL).json()

if 데이터["rows"]:
    df = pd.DataFrame(데이터["rows"])
    st.dataframe(df[["name", "times"]])
    st.caption(f"모두 {len(df)}명이 제출했습니다.")
else:
    st.info("아직 제출된 내용이 없습니다. 첫 줄을 넣어 보세요.")
✔️ 이렇게 되면 성공
  • 앱에서 이름을 적고 시간을 골라 제출 → 아래 명단에 방금 넣은 줄이 바로 보입니다
  • 스프레드시트를 열어 보면 votes 시트에 같은 줄이 생겨 있습니다. 저장소가 눈에 보이는 표라는 것이 이 방식의 큰 장점입니다
  • 앱 주소를 휴대폰이나 시크릿 창에서 열어도 같은 명단이 보입니다. 여기까지 되면 앱에 기억이 생긴 것입니다
🧯 안 될 때 보는 곳
  • Expecting value 오류 → 중계 주소가 명단 대신 로그인 화면을 돌려주는 중입니다. 배포의 액세스 권한이 '모든 사용자'인지, 금고의 주소가 …/exec로 끝나는지 확인하세요
  • 제출해도 시트에 안 쌓임 → Apps Script 코드를 고친 뒤 새 버전 배포를 안 한 상태가 대부분입니다. 배포 관리에서 새 버전으로 다시 배포하세요
  • 오류는 없는데 명단만 계속 비어 있음 → 시트 탭 이름을 손으로 바꾼 경우입니다. 이름이 바뀌면 중계 프로그램이 빈 votes 시트를 새로 만들어 그쪽만 봅니다
  • KeyError → 금고에 넣은 이름과 코드가 꺼내 쓰는 이름이 다릅니다. 두 곳 다 SHEET_API_URL인지 확인하세요

2. 오늘 다루지 않은 것

네 가지 모두 오늘 배운 방식 그대로 만들 수 있습니다. 완성 코드는 넣지 않았습니다. 프롬프트를 그대로 복사해 AI에 넣고, 돌아온 코드를 읽어 보면 됩니다.

2-1. 날씨·기후 대시보드 (Open-Meteo)

  • 인증키가 없습니다. 주소에 위도·경도와 원하는 항목을 적어 보내면 JSON이 돌아옵니다
  • 주소가 둘로 갈립니다. 앞으로 7일 예보는 api.open-meteo.com/v1/forecast, 1940년부터의 과거 기록은 archive-api.open-meteo.com/v1/archive입니다
  • 수업 소재로는 과거 쪽이 낫습니다. 학교 좌표로 30년치 여름 평균기온을 뽑으면, 기후 변화가 학생이 아는 장소의 숫자로 바뀝니다
  • 좌표는 학교 주소를 지도 서비스에서 찍어 읽으면 됩니다. 소수점 네 자리면 충분합니다
  • 항목 이름과 조건은 open-meteo.com/en/docs에서 클릭으로 고르면 주소가 만들어집니다
① 샘플 프롬프트
스트림릿으로 '우리 학교 기온 30년' 앱 하나(main.py)를 만들어줘. 스트림릿 클라우드에 올릴 거야.

- 데이터는 Open-Meteo의 과거 기록이야. 주소는 아래 하나뿐이고 인증키가 없어.
  https://archive-api.open-meteo.com/v1/archive
- 위도와 경도를 화면에서 직접 넣게 하고, 처음 값은 서울시청(37.5665, 126.9780)으로 둬.
- 1995년 1월 1일부터 작년 12월 31일까지 일별 평균기온을 받아 와.
- 연평균기온과 여름(6~8월) 평균기온을 각각 꺾은선그래프로 그려줘.
- 그래프 위에 지표 카드 두 장: 가장 최근 연도의 여름 평균기온,
  그리고 그 값이 30년 전보다 몇 도 오르내렸는지.

2-2. 논문 검색 대시보드 (OpenAlex)

  • OpenAlex는 2억 편이 넘는 논문 정보를 인증키 없이 열어 둔 서비스입니다. 주소는 api.openalex.org/works 하나이고, 뒤에 검색어와 조건을 붙여 보냅니다
  • 연도별 편수는 publication_year로 묶어 달라고 하면 한 번의 요청으로 옵니다. 논문을 한 편씩 받아 세는 방식과 속도 차이가 큽니다
  • 실제로 불러 보면 제목에 computational thinking이 든 논문은 2016년 267편에서 2025년 1300편으로 늘었습니다. 정보 교과의 흐름을 숫자로 보여 주는 자료가 됩니다
  • 주소에 mailto로 이메일을 붙이면 응답이 빠른 줄로 갑니다. OpenAlex가 안내하는 방식입니다. 돌아온 코드의 YOUR_EMAIL 자리는 본인 이메일로 바꿉니다
  • 조건 이름은 developers.openalex.org에 정리돼 있습니다

스트림릿으로 '내 분야 논문 흐름' 앱 하나(main.py)를 만들어줘. 스트림릿 클라우드에 올릴 거야.

2-3. 랜덤 뽑기·모둠 편성기

  • 데이터도 인증키도 필요 없습니다. 명단을 붙여넣으면 그 자리에서 돕니다. 이 절의 네 가지 중 가장 빨리 끝납니다
  • 발표자 뽑기, 모둠 편성, 자리 배치는 매 시간 쓰는 도구라 만든 다음 날부터 바로 쓰입니다
  • 손이 가는 부분은 무작위 자체가 아니라 규칙입니다. 한 번 뽑힌 사람은 다시 안 나오게, 특정 두 명은 같은 모둠에 묶이지 않게. 이런 조건을 어디까지 넣느냐가 앱의 쓸모를 정합니다
  • 고정 번호를 하나 두면 같은 명단에서 언제 돌려도 같은 결과가 나옵니다. 나중에 "그때 어떻게 나눴더라"를 다시 만들어 낼 수 있습니다
① 샘플 프롬프트
스트림릿으로 '모둠 편성기' 앱 하나(main.py)를 만들어줘. 스트림릿 클라우드에 올릴 거야.

2-4. 인구 피라미드·지표 카드

3. 자동화 — 정해진 시간에 컴퓨터가 대신 실행하게 하기

무료 스트림릿 앱은 방문이 한동안 없으면 잠듭니다. 다음 방문자는 깨우기 화면에서 1~2분 기다려야 합니다. 로봇에게 시간표를 주고 대신 다녀오게 하면 이 대기가 사라집니다. 그 시간표를 적는 문법이 cron입니다.

3-1. cron 다섯 칸

cron 다섯 칸의 순서
┌─────── 분 (0-59)
│ ┌───── 시 (0-23)
│ │ ┌─── 일 (1-31)
│ │ │ ┌─ 월 (1-12)
│ │ │ │ ┌ 요일 (0-6, 0이 일요일)
│ │ │ │ │
5 * * * *

5 * * * *를 왼쪽부터 읽으면 "5분에 · 매 시 · 매 일 · 매 월 · 매 요일", 곧 매시간 5분마다입니다.

기호뜻예시
*모든 값시 칸에 * = 매시간
,여러 개 열거시 칸에 0,12 = 0시와 12시
-범위요일 칸에 1-5 = 월요일부터 금요일
/간격분 칸에 */15 = 15분마다

3-2. 시각은 세계표준시(UTC)로 적습니다

  • GitHub Actions의 cron은 UTC로 해석됩니다. 한국 시간이 아닙니다
  • 한국 시간(KST) = UTC + 9시간. 그래서 원하는 한국 시간에서 9를 뺀 값을 적습니다
  • 9를 뺐더니 음수가 되면(한국 시간 09시 미만) +15를 하고 전날로 넘어갑니다. 요일 칸을 쓰고 있었다면 요일도 하루 앞으로 당겨야 합니다
원하는 시점 (한국 시간)cron
매시간 5분마다5 * * * * (분만 정하면 시차와 무관)
매일 아침 09:000 0 * * * (9−9=0)
매일 낮 12:000 3 * * * (12−9=3)
매일 아침 07:2323 22 * * * (7+15=22 · 전날)
평일(월~금) 09:000 0 * * 1-5
월요일 아침 07:000 22 * * 0 (전날이라 요일도 일요일로)
💡 확인 도구
  • crontab.guru에 다섯 칸을 넣으면 영어 문장으로 풀어 줍니다. 시차는 계산해 주지 않으니 UTC로 바꾼 값을 넣어 확인하세요
① 샘플 프롬프트 — cron 물어보기
깃허브 액션즈로 자동 실행 시간표를 만들려고 해.
한국 시간으로 평일 아침 8시 30분에 실행되게 하고 싶어.

깃허브 액션즈의 시간표(cron)는 세계표준시(UTC) 기준이라고 들었어.
다섯 칸을 어떻게 적어야 하는지 알려 주고,
한국 시간에서 어떻게 계산한 건지도 같이 설명해 줘.
요일이 하루 밀리는 경우가 있으면 그것도 알려 줘.

3-3. GitHub Actions에 얹기

  • 저장소에 .github/workflows/ 폴더를 만들고 .yml 파일 하나를 둡니다
  • 그 안에 cron과 실행할 명령을 적으면 끝입니다
.github/workflows/collect.yml
name: 데이터 수집
on:
  schedule:
    - cron: "5 * * * *"      # 매시간 5분에 실행 (UTC 기준)
  workflow_dispatch:          # 이 줄이 있으면 수동 실행 버튼도 생김
jobs:
  run:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: python collect.py
        env:
          API_KEY: ${{ secrets.API_KEY }}   # 키는 저장소 Secrets에서
  • 키는 코드에 적지 않습니다. 저장소 Settings → Secrets and variables → Actions에 넣고 이름으로 꺼내 씁니다. 앱의 비밀 금고와 같은 원리입니다
  • workflow_dispatch를 적어 두면 Actions 탭에 수동 실행 버튼이 생깁니다. 시간표를 기다리지 않고 지금 바로 시험할 수 있습니다
⚠️ 미리 알아 둘 제약 다섯
  • UTC 기준. 9시간 어긋나는 실수가 가장 흔합니다
  • 정시보다 늦게 돕니다. 무료 러너가 붐비면 몇 분 지연은 정상이라, 매시 0분보다 5분처럼 살짝 뒤를 권합니다
  • 최소 간격 5분. 1분마다 같은 설정은 그대로 동작하지 않습니다
  • 기본 브랜치에서만 시간표가 돕니다
  • 60일간 저장소에 활동이 없으면 시간표가 자동으로 멈춥니다. 안내 메일이 오면 Actions 탭에서 버튼 한 번으로 다시 켜면 됩니다
💡 앱 깨우기는 만들지 말고 가져다 쓰기
  • 스트림릿의 방문 감지는 까다로워서 단순 요청 한 번으로는 깨어나지 않습니다. 진짜 브라우저로 접속해야 합니다
  • 이 조건을 이미 통과한 완성본이 github.com/greatsong/app-caretaker에 템플릿으로 있습니다. Use this template → Create a new repository로 내 계정에 복사하고, apps.txt에 내 앱 주소를 적은 뒤 Actions 탭에서 Run workflow를 한 번 누르면 됩니다
  • Fork가 아니라 Use this template이어야 합니다. 포크한 저장소에서는 시간표가 돌지 않습니다
  • 앱을 알릴 일이 끝나면 Actions 탭에서 Disable workflow로 꺼 두는 편이 낫습니다. 스트림릿이 앱을 재우는 건 무료 자원을 아끼기 위해서입니다
