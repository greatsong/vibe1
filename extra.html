1. 데이터가 쌓이는 앱 — Supabase

오늘 만든 앱은 새로고침하면 화면에 넣은 내용이 사라집니다. 저장소를 하나 붙이면 남습니다. 여기서 만드는 것은 약속 잡기 앱입니다. 이름과 가능한 시간을 제출하면 표에 한 줄씩 쌓이고, 다른 사람이 다른 기기에서 열어도 그대로 보입니다.

  • Supabase = 앱을 위해 만들어진 무료 데이터베이스. 카드 등록 없이 씁니다
  • 앱에서 연결에 필요한 것은 주소 한 줄과 키 한 줄. 오늘 STEP 2에서 다룬 비밀 금고(secrets) 방식 그대로입니다
  • 준비 15분, 앱 만들기 15분 정도 걸립니다

1-1. 프로젝트와 테이블 만들기

  1. 가입하고 새 프로젝트 만들기
    supabase.com에서 GitHub 계정이나 이메일로 가입합니다. 카드 등록은 없습니다. 처음이면 조직(organization) 만들기가 먼저 나옵니다. 이름을 아무거나 정하고 통과한 뒤 New project를 눌러 프로젝트 이름과 데이터베이스 비밀번호를 정하세요. 리전은 기본값 그대로 둡니다. 준비에 2분 안팎 걸리니 그동안 새로고침하거나 다시 누르지 마세요. 대시보드가 열리면 다음으로 넘어갑니다.
  2. SQL 한 번 실행 — 테이블과 정책을 함께
    왼쪽 SQL Editor → New query를 열고 아래 상자를 그대로 붙여넣은 뒤 Run을 누릅니다. Success. No rows returned가 뜨면 됩니다. 클릭으로 만들 수도 있지만, 그러면 열 이름을 손으로 치게 되고 name을 names로 적는 순간 앱이 안 돌아갑니다.
  3. 주소와 키 복사
    Settings → API Keys에서 publishable 키를, Settings → Data API에서 Project URL을 복사합니다. 문자열 두 개가 전부입니다. URL은 반드시 .supabase.co에서 끝나야 합니다. 뒤에 /rest/v1 같은 게 붙어 있으면 그 부분은 지우세요. 안 지우면 나중에 PGRST125 Invalid path 오류가 납니다. (화면 구성은 조금씩 바뀔 수 있습니다. 못 찾으면 AI에게 물어보세요)
SQL Editor에 그대로 붙여넣고 Run
create table votes (
  id bigint generated always as identity primary key,
  name text,
  times text,
  created_at timestamptz default now()
);

alter table votes enable row level security;

create policy "누구나 읽기" on votes
  for select to anon, authenticated using (true);

create policy "누구나 쓰기" on votes
  for insert to anon, authenticated with check (true);
  • 네 문장이 한 번에 돌아갑니다. votes 테이블(열 name·times·created_at)이 생기고, 잠금이 켜진 뒤, 읽기와 쓰기를 열어 주는 정책이 하나씩 붙습니다
  • 테이블 이름은 votes처럼 글자로 시작해야 합니다. 260729 같은 숫자만으로는 안 됩니다
  • created_at은 데이터베이스가 알아서 채웁니다. 앱에서 보낼 필요가 없습니다
⚠️ 행 수준 보안(RLS)이 조용히 막습니다
  • Supabase는 새 테이블에 행 수준 보안(RLS)을 걸 수 있고, 걸리면 기본값이 전부 차단입니다. 정책을 하나도 안 만들면 아무것도 통과하지 못합니다
  • 막히는 모습이 둘로 갈립니다. 저장은 row-level security 문구가 든 빨간 오류로 바로 드러나는데, 읽기는 오류 없이 빈 목록이 옵니다. 코드는 멀쩡해 보이는데 명단만 계속 비어 있습니다
  • 그래서 위 SQL에 테이블과 정책을 함께 넣었습니다. 읽기 정책과 쓰기 정책이 하나씩 있어야 앱이 돕니다
  • 관리자 화면(Table Editor)에서 직접 줄을 넣어 보는 것으로는 확인이 안 됩니다. 관리자 화면은 RLS를 거치지 않고 통과합니다. 확인은 반드시 배포한 앱에서 하세요
  • 정책이 제대로 붙었는지 보려면 Table Editor에서 votes를 열어 보세요. 이름 옆에 Unrestricted 배지가 없고 정책 수가 2로 표시되면 위 SQL이 다 돌아간 상태입니다
🔑 키 두 종류를 구분합니다
  • publishable 키(sb_publishable_로 시작) = 앱에 넣어도 되는 공개용. 여기서 쓰는 키입니다. 이 키로 들어온 요청은 위에서 만든 정책이 허용한 범위 안에서만 움직입니다
  • secret 키(sb_secret_로 시작) = 모든 잠금을 여는 관리자 키. 앱에도, GitHub에도 올리지 않습니다
  • 2025년 11월 이전에 만든 프로젝트라면 옛 이름인 anon·service_role 키가 보일 수 있습니다. 각각 publishable·secret에 해당합니다

1-3. AI에게 주문하기

① 샘플 프롬프트
스트림릿으로 '약속 잡기' 앱 하나(app.py)를 만들어줘. 스트림릿 클라우드에 올릴 거야.

- 데이터 저장소는 Supabase야. 접속에 필요한 주소와 키는
  비밀 금고(secrets)의 SUPABASE_URL, SUPABASE_KEY에서 꺼내 써. 코드에는 적지 마.
- 테이블 이름은 votes, 열은 name(글자), times(글자), created_at(제출 시각)이야.
  created_at은 데이터베이스가 알아서 채우니까 앱에서 보내지 마.
- 화면 위에 이름 입력창, 가능한 시간을 여러 개 고르는 목록, 제출 버튼을 둬.
  시간 목록은 '월 오전'부터 '금 오후'까지 요일과 오전·오후를 짝지은 열 개로.
- 제출을 누르면 이름과 고른 시간을 votes 테이블에 한 줄 추가해줘.
  여러 개 고른 시간은 쉼표로 이어 붙여서 times 한 칸에 넣어.
- 이름이 비었거나 시간을 하나도 안 골랐으면 저장하지 말고 안내 문구만 띄워.
- 그 아래에는 votes 테이블 전체를 최근 제출 순으로 읽어 와 표로 보여줘.
  표에는 이름과 시간 두 열만 보이면 돼.
  아직 한 줄도 없으면 표 대신 비어 있다는 안내를 띄워.
- 필요한 라이브러리 목록(requirements.txt)도 같이 줘.
  버전 숫자 없이 이름만, 스트림릿·판다스·넘파이는 기본 설치라 빼고.
- 한국어 라벨, 초보자용 한국어 주석. app.py 전체 코드를 한 번에 줘.
  • AI가 아래와 같은 모습의 코드를 줍니다. 글자까지 똑같지 않아도 됩니다
② AI가 준 코드 예시 (app.py)
import streamlit as st
from supabase import create_client
import pandas as pd

# 비밀 금고(secrets)에 넣어 둔 두 줄을 꺼내 Supabase에 연결합니다
url = st.secrets["SUPABASE_URL"]
key = st.secrets["SUPABASE_KEY"]
supabase = create_client(url, key)

st.set_page_config(page_title="약속 잡기", page_icon="📅")
st.title("📅 약속 잡기")
st.write("가능한 시간을 골라 제출하면 아래 명단에 한 줄씩 쌓입니다.")

시간목록 = [
    "월 오전", "월 오후", "화 오전", "화 오후", "수 오전",
    "수 오후", "목 오전", "목 오후", "금 오전", "금 오후",
]

이름 = st.text_input("이름")
선택시간 = st.multiselect("가능한 시간을 모두 고르세요", 시간목록)

if st.button("제출"):
    if not 이름:
        st.warning("이름을 적어 주세요.")
    elif not 선택시간:
        st.warning("가능한 시간을 하나 이상 골라 주세요.")
    else:
        # 여러 개 고른 시간은 쉼표로 이어 한 칸에 넣습니다
        supabase.table("votes").insert(
            {"name": 이름, "times": ", ".join(선택시간)}
        ).execute()
        st.success(f"{이름} 선생님, 제출됐습니다.")

st.divider()
st.subheader("📋 지금까지 제출된 명단")

# votes 테이블 전체를 최근 제출 순으로 읽어 옵니다
응답 = (
    supabase.table("votes")
    .select("name, times, created_at")
    .order("created_at", desc=True)
    .execute()
)

if 응답.data:
    df = pd.DataFrame(응답.data)
    st.dataframe(df[["name", "times"]])
    st.caption(f"모두 {len(df)}명이 제출했습니다.")
else:
    st.info("아직 제출된 내용이 없습니다. 첫 줄을 넣어 보세요.")
✔️ 이렇게 되면 성공
  • 앱에서 이름을 적고 시간을 골라 제출 → 아래 명단에 방금 넣은 줄이 바로 보입니다
  • Supabase의 Table Editor → votes를 열어 새로고침 → 같은 줄이 있으면 확실합니다
  • 앱 주소를 휴대폰이나 시크릿 창에서 열어도 같은 명단이 보입니다. 여기까지 되면 앱에 기억이 생긴 것입니다
🧯 안 될 때 보는 곳
  • 빨간 오류에 row-level security → 쓰기 정책이 없는 상태. 1-1의 SQL에서 정책 두 개를 다시 실행하세요
  • 오류는 없는데 명단만 계속 비어 있음 → 읽기 정책이 없는 상태. 원인은 바로 위와 같습니다
  • PGRST205 · Could not find the table → 테이블 이름이 다르거나 다른 프로젝트를 가리키는 중
  • PGRST125 · Invalid path → 금고의 SUPABASE_URL 끝에 /rest/v1이 붙어 있습니다. .supabase.co까지만 남기세요
  • KeyError → 금고에 넣은 이름과 코드가 꺼내 쓰는 이름이 다릅니다. 두 곳 다 SUPABASE_URL·SUPABASE_KEY인지 확인하세요

2. 오늘 다루지 않은 것

네 가지 모두 오늘 배운 방식 그대로 만들 수 있습니다. 완성 코드는 넣지 않았습니다. 프롬프트를 그대로 복사해 AI에 넣고, 돌아온 코드를 읽어 보면 됩니다.

2-1. 날씨·기후 대시보드 (Open-Meteo)

  • 인증키가 없습니다. 주소에 위도·경도와 원하는 항목을 적어 보내면 JSON이 돌아옵니다
  • 주소가 둘로 갈립니다. 앞으로 7일 예보는 api.open-meteo.com/v1/forecast, 1940년부터의 과거 기록은 archive-api.open-meteo.com/v1/archive입니다
  • 수업 소재로는 과거 쪽이 낫습니다. 학교 좌표로 30년치 여름 평균기온을 뽑으면, 기후 변화가 학생이 아는 장소의 숫자로 바뀝니다
  • 좌표는 학교 주소를 지도 서비스에서 찍어 읽으면 됩니다. 소수점 네 자리면 충분합니다
  • 항목 이름과 조건은 open-meteo.com/en/docs에서 클릭으로 고르면 주소가 만들어집니다
① 샘플 프롬프트
스트림릿으로 '우리 학교 기온 30년' 앱 하나(app.py)를 만들어줘. 스트림릿 클라우드에 올릴 거야.

- 데이터는 Open-Meteo의 과거 기록이야. 주소는 아래 하나뿐이고 인증키가 없어.
  https://archive-api.open-meteo.com/v1/archive
- 위도와 경도를 화면에서 직접 넣게 하고, 처음 값은 서울시청(37.5665, 126.9780)으로 둬.
- 1995년 1월 1일부터 작년 12월 31일까지 일별 평균기온을 받아 와.
- 연평균기온과 여름(6~8월) 평균기온을 각각 꺾은선그래프로 그려줘.
- 그래프 위에 지표 카드 두 장: 가장 최근 연도의 여름 평균기온,
  그리고 그 값이 30년 전보다 몇 도 오르내렸는지.
- 값이 비어 있는 날이 섞여 올 수 있어.
- 응답이 실패하면 무엇을 확인해야 하는지 한국어로 안내해 줘.
- 필요한 라이브러리 목록(requirements.txt)도 같이 줘.
  버전 숫자 없이 이름만, 스트림릿·판다스·넘파이는 기본 설치라 빼고.
- 한국어 라벨, 초보자용 한국어 주석. app.py 전체 코드를 한 번에 줘.

2-2. 논문 검색 대시보드 (OpenAlex)

  • OpenAlex는 2억 편이 넘는 논문 정보를 인증키 없이 열어 둔 서비스입니다. 주소는 api.openalex.org/works 하나이고, 뒤에 검색어와 조건을 붙여 보냅니다
  • 연도별 편수는 publication_year로 묶어 달라고 하면 한 번의 요청으로 옵니다. 논문을 한 편씩 받아 세는 방식과 속도 차이가 큽니다
  • 실제로 불러 보면 제목에 computational thinking이 든 논문은 2016년 267편에서 2025년 1300편으로 늘었습니다. 정보 교과의 흐름을 숫자로 보여 주는 자료가 됩니다
  • 주소에 mailto로 내 이메일을 붙이면 응답이 빠른 줄로 갑니다. OpenAlex가 안내하는 방식입니다
  • 조건 이름은 developers.openalex.org에 정리돼 있습니다
① 샘플 프롬프트
스트림릿으로 '내 분야 논문 흐름' 앱 하나(app.py)를 만들어줘. 스트림릿 클라우드에 올릴 거야.

- 데이터는 OpenAlex야. 주소는 https://api.openalex.org/works 이고 인증키가 없어.
  주소에 mailto로 내 이메일을 붙이면 응답이 빠른 줄로 가니까 그렇게 해줘.
- 화면 맨 위에 영어 검색어 입력창을 두고, 처음 값은 computational thinking으로.
- 제목에 그 검색어가 든 논문만, 2010년 이후로 한정해서 세어 줘.
  결과가 수천 편이라 한 편씩 다 받아 오면 앱이 멈춰. 편수만 세어서 받아 와.
- 연도별 편수를 막대그래프로 그리고, 지표 카드 두 장으로
  전체 편수와 가장 많이 나온 연도를 보여 줘.
- 그 아래에는 인용이 많은 순으로 상위 10편을 표로. 제목·발표연도·인용수 세 열만.
- 올해와 작년은 아직 등록이 덜 끝나 편수가 낮게 보인다는 안내를
  그래프 아래에 한 줄 적어 줘.
- 검색어가 비었거나 결과가 하나도 없으면 그래프 대신 안내 문구만 띄워.
- 필요한 라이브러리 목록(requirements.txt)도 같이 줘.
  버전 숫자 없이 이름만, 스트림릿·판다스·넘파이는 기본 설치라 빼고.
- 한국어 라벨, 초보자용 한국어 주석. app.py 전체 코드를 한 번에 줘.

2-3. 랜덤 뽑기·모둠 편성기

  • 데이터도 인증키도 필요 없습니다. 명단을 붙여넣으면 그 자리에서 돕니다. 이 절의 네 가지 중 가장 빨리 끝납니다
  • 발표자 뽑기, 모둠 편성, 자리 배치는 매 시간 쓰는 도구라 만든 다음 날부터 바로 쓰입니다
  • 손이 가는 부분은 무작위 자체가 아니라 규칙입니다. 한 번 뽑힌 사람은 다시 안 나오게, 특정 두 명은 같은 모둠에 묶이지 않게. 이런 조건을 어디까지 넣느냐가 앱의 값을 정합니다
  • 고정 번호를 하나 두면 같은 명단에서 언제 돌려도 같은 결과가 나옵니다. 나중에 "그때 어떻게 나눴더라"를 다시 만들어 낼 수 있습니다
① 샘플 프롬프트
스트림릿으로 '모둠 편성기' 앱 하나(app.py)를 만들어줘. 스트림릿 클라우드에 올릴 거야.

- 외부 데이터도 인증키도 쓰지 않아. 명단은 화면에서 직접 넣어.
- 위쪽에 여러 줄 입력창을 두고, 한 줄에 한 명씩 이름을 붙여넣게 해.
- 모둠 수와 모둠당 인원 중 하나를 골라 정하게 해.
- 편성 버튼을 누르면 무작위로 나눠서 모둠별로 나란히 보여 줘.
- 고정 번호를 넣는 칸을 두고, 같은 번호와 같은 명단이면
  언제 돌려도 같은 편성이 나오게 해.
- '같은 모둠에 넣지 않을 짝'을 이름 두 개씩 적는 칸을 두고, 그 짝은 떨어뜨려 줘.
- 결과를 복사하는 버튼과 파일로 내려받는 버튼을 둬.
- 발표자 한 명을 뽑는 화면도 따로 만들어. 뽑힌 사람은 다음 뽑기에서 빼 줘.
- 필요한 라이브러리 목록(requirements.txt)도 같이 줘.
  버전 숫자 없이 이름만, 스트림릿·판다스·넘파이는 기본 설치라 빼고.
- 한국어 라벨, 초보자용 한국어 주석. app.py 전체 코드를 한 번에 줘.

2-4. 인구 피라미드·지표 카드

  • STEP 1에서 쓴 인구 파일에는 시군구 합계뿐 아니라 읍·면·동 단위 1세 인구가 다 들어 있습니다. 같은 파일로 앱을 하나 더 만들 수 있습니다
  • 지도는 어디가 늙었는지를 보여 주고, 피라미드는 그 동네가 어떤 모양으로 늙었는지를 보여 줍니다. 둘을 같이 놓으면 학생이 읽을 거리가 생깁니다
  • 열 이름은 연도·시도·시군구·동·코드 다음에 계_0세부터 계_100세 이상, 이어서 남_0세·여_0세가 같은 방식으로 붙습니다. 2015~2026년이 한 파일에 있습니다
  • 자주 어긋나는 곳이 둘입니다. 막대가 한쪽으로만 자라거나, 나이 순서가 뒤섞여 0세와 100세가 붙어 나옵니다. 그래서 프롬프트에 남자는 왼쪽·여자는 오른쪽, 0세가 맨 아래·100세 이상이 맨 위를 적어 둡니다
① 샘플 프롬프트
스트림릿으로 '동네별 인구 피라미드' 앱 하나(app.py)를 만들어줘. 스트림릿 클라우드에 올릴 거야.

- 데이터는 이 주소의 CSV야:
  https://raw.githubusercontent.com/greatsong/modudata/main/data/population_yearly.csv.gz
- 2015~2026년 전국 읍·면·동 인구가 다 들어 있어. 가장 최신 연도만 골라 써.
- 표에는 연도·시도·시군구·동 열이 있고, 0세부터 100세 이상까지 남녀 인구가
  '남_0세', '여_0세', '남_100세 이상' 형식의 열로 있어.

  남자는 왼쪽, 여자는 오른쪽, 세로축은 나이.
  0세가 맨 아래, 100세 이상이 맨 위로 놓이게 해줘.
- 가로축 눈금은 양쪽 다 인구 수로 보여 줘.
- 그래프 위에 지표 카드 세 장: 총인구, 평균연령, 고령화율(65세 이상 비율, %).
- 그래프 아래에 이 동네가 아이가 많은 편인지 어르신이 많은 편인지

- 필요한 라이브러리 목록(requirements.txt)도 같이 줘.

3. 자동화 — 정해진 시간에 컴퓨터가 대신

무료 스트림릿 앱은 방문이 한동안 없으면 잠듭니다. 다음 방문자는 깨우기 화면에서 1~2분 기다려야 합니다. 로봇에게 시간표를 주고 대신 다녀오게 하면 이 대기가 사라집니다. 그 시간표를 적는 문법이 cron입니다.

3-1. cron 다섯 칸

cron 다섯 칸의 순서
┌─────── 분 (0-59)
│ ┌───── 시 (0-23)
│ │ ┌─── 일 (1-31)
│ │ │ ┌─ 월 (1-12)
│ │ │ │ ┌ 요일 (0-6, 0이 일요일)
│ │ │ │ │
5 * * * *

5 * * * *를 왼쪽부터 읽으면 "5분에 · 매 시 · 매 일 · 매 월 · 매 요일", 곧 매시간 5분마다입니다.

기호뜻예시
*모든 값시 칸에 * = 매시간
,여러 개 열거시 칸에 0,12 = 0시와 12시
-범위요일 칸에 1-5 = 월요일부터 금요일
/간격분 칸에 */15 = 15분마다

3-2. 시각은 세계표준시(UTC)로 적습니다

  • GitHub Actions의 cron은 UTC로 해석됩니다. 한국 시간이 아닙니다
  • 한국 시간(KST) = UTC + 9시간. 그래서 원하는 한국 시간에서 9를 뺀 값을 적습니다
  • 9를 뺐더니 음수가 되면(한국 시간 09시 미만) +15를 하고 전날로 넘어갑니다. 요일 칸을 쓰고 있었다면 요일도 하루 앞으로 당겨야 합니다
원하는 시점 (한국 시간)cron
매시간 5분마다5 * * * * (분만 정하면 시차와 무관)
매일 아침 09:000 0 * * * (9−9=0)
매일 낮 12:000 3 * * * (12−9=3)
매일 아침 07:2323 22 * * * (7+15=22 · 전날)
평일(월~금) 09:000 0 * * 1-5
월요일 아침 07:000 22 * * 0 (전날이라 요일도 일요일로)
💡 확인 도구
  • crontab.guru에 다섯 칸을 넣으면 영어 문장으로 풀어 줍니다. 시차는 계산해 주지 않으니 UTC로 바꾼 값을 넣어 확인하세요
① 샘플 프롬프트 — cron 물어보기
깃허브 액션즈로 자동 실행 시간표를 만들려고 해.
한국 시간으로 평일 아침 8시 30분에 실행되게 하고 싶어.

깃허브 액션즈의 시간표(cron)는 세계표준시(UTC) 기준이라고 들었어.
다섯 칸을 어떻게 적어야 하는지 알려 주고,
한국 시간에서 어떻게 계산한 건지도 같이 설명해 줘.
요일이 하루 밀리는 경우가 있으면 그것도 알려 줘.

3-3. GitHub Actions에 얹기

  • 저장소에 .github/workflows/ 폴더를 만들고 .yml 파일 하나를 둡니다
  • 그 안에 cron과 실행할 명령을 적으면 끝입니다
.github/workflows/collect.yml
name: 데이터 수집
on:
  schedule:
    - cron: "5 * * * *"      # 매시간 5분에 실행 (UTC 기준)
  workflow_dispatch:          # 이 줄이 있으면 수동 실행 버튼도 생김
jobs:
  run:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: python collect.py
        env:
          API_KEY: ${{ secrets.API_KEY }}   # 키는 저장소 Secrets에서
  • 키는 코드에 적지 않습니다. 저장소 Settings → Secrets and variables → Actions에 넣고 이름으로 꺼내 씁니다. 앱의 비밀 금고와 같은 원리입니다
  • workflow_dispatch를 적어 두면 Actions 탭에 수동 실행 버튼이 생깁니다. 시간표를 기다리지 않고 지금 바로 시험할 수 있습니다
⚠️ 미리 알아 둘 제약 다섯
  • UTC 기준. 9시간 어긋나는 실수가 가장 흔합니다
  • 정시보다 늦게 돕니다. 무료 러너가 붐비면 몇 분 지연은 정상이라, 매시 0분보다 5분처럼 살짝 뒤를 권합니다
  • 최소 간격 5분. 1분마다 같은 설정은 그대로 동작하지 않습니다
  • 기본 브랜치에서만 시간표가 돕니다
  • 60일간 저장소에 활동이 없으면 시간표가 자동으로 멈춥니다. 안내 메일이 오면 Actions 탭에서 버튼 한 번으로 다시 켜면 됩니다
💡 앱 깨우기는 만들지 말고 가져다 쓰기
  • 스트림릿의 방문 감지는 까다로워서 단순 요청 한 번으로는 깨어나지 않습니다. 진짜 브라우저로 접속해야 합니다
  • 이 조건을 이미 통과한 완성본이 github.com/greatsong/app-caretaker에 템플릿으로 있습니다. Use this template → Create a new repository로 내 계정에 복사하고, apps.txt에 내 앱 주소를 적은 뒤 Actions 탭에서 Run workflow를 한 번 누르면 됩니다
  • Fork가 아니라 Use this template이어야 합니다. 포크한 저장소에서는 시간표가 돌지 않습니다
  • 앱을 알릴 일이 끝나면 Actions 탭에서 Disable workflow로 꺼 두는 편이 낫습니다. 스트림릿이 앱을 재우는 건 무료 자원을 아끼기 위해서입니다
